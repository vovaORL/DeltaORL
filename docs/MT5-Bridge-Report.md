# Звіт підготовки сумісного DeltaBridge 1.20 Bid

Кандидат підготовлено до окремого підтвердження встановлення. Робочі mq5/ex5 у Wine не замінено: їхні SHA-256 збігаються з постійною резервною копією в `/home/volodymyr/Backups/DeltaORL-bridge-20261112-162510`. Робочі процеси engine та MT5 не перезапускалися. Позиції, параметри рахунку та торгові операції не зачіпалися; git push не виконувався.

## Результат

Ціна графіка — оригінальний Bid. Окремі історичний/live класифікатори 1.00 збережені, включно з особливостями обробки Last; евристичне походження сторони записується в аудит. У HELLO передається брокерський tick size, без таблиць значень за символами. Штучних тіків із M1 немає. Транспорт враховує позиції всіх записів граничної мілісекунди, включно з ідентичними, змінами лише Ask і непридатними котировками. Помилки копіювання не видаються за успішне завершення історії.

C++ алгоритми агрегації, UI, графіки, дельта, CVD, індикатори та торгові правила не змінювалися на цьому етапі.

Поточний C++ інсталятор не копіює mqh; майбутнє встановлення кандидата має використати перевірений build/mt5/ex5, а для джерел — mq5 разом із mqh. Інсталятор/UI не переписувалися.

## Автоматизовані перевірки

- Нативна CMake-збірка та CTest: **1/1**, успішно.
- Python suite: **28 тестів**, успішно.
- Код EA виконувався в тестовій підстановці MQL API; MetaEditor незалежно перевірив MQL-компіляцію.
- Історичний та live-класифікатори порівняно на 10000 записів з функціями, витягнутими з незміненого архіву 1.00.
- Перевірено історичні/live ідентичні записи, зміни лише Ask, дописування на граничній мілісекунді, повторне опитування без дублювання, підміну префікса, некоректні котировки та NaN на межі.
- Перевірено часткові відправки TCP, додатний результат CopyTicksRange разом із помилкою 4403, відновлення сесії, довгу паузу між котировками, ліміт історії та випадок понад 200000 записів однієї мілісекунди.
- 200000 повідомлень, сформованих кодом кандидата, передано в справжній нативний engine на ізольованому TCP-порту. Перевірено Bid-OHLC, обсяг, M1 → M15 → M1 і повторне відтворення сесії без подвоєння обсягу.
- Незалежний receiver-тест перевіряє Bid/Ask, time_msc, однакові мітки та порядок приймання.
- Діагностичні тести виявляють втрачений ідентичний запис, зміну лише Ask, перестановку записів, помилку синхронізації, хибну межу history/live, OHLC-розбіжність в один брокерський крок та непокритий хвіст еталона. Поточна свічка engine не порівнюється як завершена.

Ці контрольні дані не є котировками брокера і не підтверджують реального підключення.

## Продуктивність незміненого агрегатора

Release-подібна компіляція `-O3`, брокерський крок 0.00001, 200000 контрольних тіків:

| Сценарій | Обробка тіків | M1 snapshot | M15 rebuild + snapshot | Повернення M1 + snapshot |
|---|---:|---:|---:|---:|
| Рух котировок, повторні мілісекунди | 0.041 с | 0.103 с | 0.022 с | 0.133 с |
| Щільні 2001 ціновий рівень | 0.014 с | 0.003 с | 0.011 с | 0.013 с |

Пікова RSS процесу: 58096 KiB, приблизно 56.7 MiB. Обидва M1-знімки після повернення з M15 збіглися побайтово; CVD зберігся. У першому сценарії M1 snapshot становив приблизно 4.06 MB. Це вимір агрегатора, а не швидкості промальовування UI, Wine/MT5, мережі чи CSV-аудиту. За цих двох сценаріїв проблеми продуктивності агрегатора не виявлено; його алгоритми не змінювалися.

## Відмінності й уточнення реалізації

Змін погоджених правил ціни, сторони та кроку понад план немає. Практичні уточнення:

- Чисті функції класифікації винесено в mqh для спільного виконання в MQL і нативних тестах.
- Весь видимий історичний префікс проходить класифікатор навіть при подальшому обрізанні збережених даних лімітом 200000. Непридатні записи враховуються діагностикою, але не впливають на стан класифікації придатних.
- Повнота брокерського покриття ніколи не оголошується доведеною лише за успіхом API; стан READY відокремлено від такої оцінки.
- Еталонний скрипт приймає точні мілісекундні межі, без перетворення через часовий пояс Linux.
- Діагностика використовує окремий, явно запусканий TCP relay для захоплення потоку без зміни engine. Сам факт пересилання не є ACK обробки.
- Поточна свічка знімка виключається з перевірки завершених OHLC; відсутні engine-свічки та хвіст еталонного потоку явно лишаються неперевіреними.

## Що залишилося перевірити

Після окремого дозволу на встановлення потрібні справжня сесія EURUSD, незалежний CopyTicksRange/CopyRates-експорт із того самого MT5, звірка полів/кількості/порядку, завершених M1/M15 та фактичний перезапуск MT5. Продуктивність самого радника у Wine з аудитом також ще не вимірювалася на брокерському потоці.

Без унікальних ID записів MT5 та ACK поточного протоколу немає абсолютної гарантії exactly-once доставки при довільних обривах/переписуванні історії. Реалізація перевіряє стабільний граничний префікс, зберігає кратність однакових записів і відновлює повну сесію після помилки. Ретроспективні зміни старішої історії перевіряються незалежним експортом. Обрізані краї, відсутні інтервали та непридатні записи не повинні подаватися як повне покриття.
