# Кандидат DeltaBridge 1.20 Bid для Wine / Linux

Статус: підготовлено та скомпільовано **кандидат**, встановлені файли MT5 не замінено. Наступне встановлення потребує підтвердження користувача. Торгових викликів у раднику та скрипті експорту немає.

Постійна резервна копія встановлених mq5/ex5 і попередніх файлів проєкту:
`/home/volodymyr/Backups/DeltaORL-bridge-20261112-162510/manifest.json`.
Маніфест містить SHA-256; фінальна перевірка підтвердила незмінність встановлених mq5/ex5.

## Що реалізовано

- `mql5/DeltaBridge.mq5` версії 1.20 і `DeltaBridgeCore.mqh`: оригінальний Bid у полі price, оригінальні Bid/Ask/time_msc, фактичний `SYMBOL_TRADE_TICK_SIZE` у HELLO. Потрібний `SYMBOL_CHART_MODE_BID`; підміни tick size значенням 0.0001 немає.
- Історичний і поточний класифікатори 1.00 збережено окремо. Зокрема збережено особливість live-класифікатора: Last усередині спреду порівнюється з попереднім Bid. Її не виправлено непомітно. На новій сесії обидва стани очищаються; історія не прогріває live-класифікатор.
- Без торгових прапорців сторона позначається `heuristic` або `unknown` в аудиті. Обсяг: volume_real → volume → 1, як у 1.00. Це не гарантує фактичний торговий обсяг або напрямок агресора на Forex і не обіцяє рівність volume із MT5 tick_volume.
- HELLO / INFO / TICK / READY, повна передача TCP-пакетів, перепідключення. INFO містить ідентифікатор сесії.
- Тільки CopyTicksRange/COPY_TICKS_ALL: окремі записи, ідентичні записи та зміни лише Ask зберігаються. Дедуплікація за ціною або однією мілісекундою відсутня. Зіставляється повний уже оброблений префікс граничної мілісекунди, включно з некоректними записами. Зміна префікса завершує сесію замість припущення про пропуск.
- Live-курсор просувається після успішної передачі пакета. Часткова відправка закриває з'єднання; наступна сесія повністю відновлює історію через HELLO. Підтверджень приймання окремих тіків протокол не має: SocketSend не означає, що engine вже обробив дані.
- Некоректні котировки не передаються як TICK, враховуються в аудиті з причиною та не прогрівають класифікатор. Їхні сирі позиції враховуються курсором, тому вони не перечитуються нескінченно. Некоректний час/порушення порядку завершує сесію з діагностикою.
- Немає CopyRates → TICK, штучних цін/часу зі свічок або midpoint як заміни Bid.
- Запити історії розбиті на годинні інтервали. Будь-яка помилка CopyTicksRange, включно з timeout при додатній кількості записів, завершує сесію без READY. Останні 200000 записів утримуються кільцевим буфером; source_count, dropped, source_invalid, межі й перший утриманий запис записуються окремо. Класифікатор історії проходить також префікс, що згодом відкидається лімітом.
- Початок запиту для InpHistoryDays > 0 округляється вниз до M15. При InpHistoryDays=0 завантажується лише початкова гранична мілісекунда для встановлення курсора; це не повна історія.
- READY означає завершення початкової передачі. У звітах покриття завжди `unverified`: успішний API-запит не доводить повноту серверної історії. CSV/помилки та порівняння з CopyRates перевіряються окремо.

## Артефакти й компіляція

```bash
PYTHONDONTWRITEBYTECODE=1 python3 tools/compile_mt5.py
```

Компілятор — окрема копія MetaEditor у `build/mt5-compiler`, з режимом portable. Джерела копіюються в `build/mt5`, ex5/log залишаються там. Радники не запускаються. Скрипт перевіряє незмінність встановлених mq5/ex5 і записує `build/mt5/compile-report.json`.

Кандидат: `build/mt5/DeltaBridge.ex5`; незалежний скрипт еталонного експорту: `build/mt5/DeltaBridgeAudit.ex5`. **Старий `mql5/DeltaBridge.ex5` не оновлювався і не є цим кандидатом.**

Штатний інсталятор UI не копіює новий mqh; його для розгортання кандидата не використовувати. C++ інсталятор та UI не змінювалися за межами погодженого обсягу.

## Майбутнє встановлення — лише після підтвердження

1. В MT5 через File → Open Data Folder визначити фактичну папку даних. Від'єднати попередній DeltaBridge і переконатися, що інша його копія не прикріплена.
2. Після дозволу скопіювати скомпільований кандидат у MQL5/Experts. Для зберігання/компіляції джерел поруч потрібні **обидва** DeltaBridge.mq5 і DeltaBridgeCore.mqh. Скрипт DeltaBridgeAudit.ex5 встановлюється окремо в MQL5/Scripts.
3. Tools → Options → Expert Advisors → Allow WebRequest for listed URL: додати `http://127.0.0.1`. Цей перелік використовується також SocketConnect. DLL та дозвіл торгівлі для читання котирувань не потрібні; параметри рахунку не змінювати.
4. Прикріпити одну копію кандидата до точного EURUSD брокера. Параметри: IP 127.0.0.1, port 9190, history days 2, send book false, audit true. Підтвердити у журналі chart=Bid, digits=5 і реальний tick_size (очікуване значення перевіряється з MT5, а не виводиться з digits).
5. Погоджено завершити старий engine і запустити актуальний Linux engine з `--bridge`; Linux Electron використовує цей режим. Windows Python і симулятор не потрібні.

Адреси MQL5 SocketConnect: https://www.mql5.com/en/docs/network/socketconnect

## Реальна звірка після встановлення

Логи радника: `MQL5/Files/DeltaBridge/<session>-ticks.csv` і `-events.csv`. У ticks є sequence (переданий/облікований утриманий потік) та source_sequence (позиція сирого потоку від requested_from, з урахуванням dropped). Запис sent означає успішний SocketSend, не підтвердження обробки engine.

Для повного захоплення початку сесії потрібний явно організований діагностичний запуск. Engine слухає інший порт, relay зберігає для MT5 адресу 127.0.0.1:9190. **Не виконувати ці команди паралельно зі старим engine на тих самих портах.**

```bash
./build/delta_engine --bridge --mt5-port 19190 --ws-port 9191
```

В окремому терміналі:

```bash
python3 tools/mt5_capture.py --listen-port 9190 --engine-port 19190 --output build/mt5/wire.jsonl
```

Relay передає дані без модифікацій і записує обидва напрямки. Він не є пасивним sniffer: на час діагностики займає порт 9190. Сам журнал пересилання не доводить, що engine обробив кожен рядок; це звіряється зі знімками/контрольними тестами receiver.

```bash
python3 tools/mt5_status.py --seconds 15 --snapshot build/mt5/engine-m1.json
```

Для другого знімка вибрати M15 у вже відкритому DeltaORL та виконати команду з `--snapshot build/mt5/engine-m15.json`. Потім повернути M1 і повторити для перевірки відновлення. Діагностика не змінює таймфрейм: зберігає останній отриманий snapshot, а не реконструює його з live-повідомлень. Остання свічка кожного знімка консервативно вважається поточною й не використовується для порівняння завершених OHLC: записується verification_closed_before. Це запобігає хибній розбіжності, якщо свічка закрилася вже після отримання знімка. Знімок містить до 1000 свічок; відсутні в ньому придатні свічки окремо позначаються неперевіреними.

Зупинити діагностичну сесію після погодженого спостереження. Для незалежного експорту запустити **read-only** DeltaBridgeAudit на тому самому символі MT5:

- InpFromMsc: точне requested_from з history у events.csv;
- InpToMsc: time_msc останнього запису закінченого аудиту; він не може перевищувати час останнього доступного тіка MT5;
- мілісекунди передаються числом без перетворення через часовий пояс Linux.

Експорт у `MQL5/Files/DeltaBridgeAudit`: ticks, rates M1/M15, requests із кодами помилок, metadata. CopyRates використовується лише як еталон і ніколи не живить engine.

```bash
python3 tools/verify_mt5.py \
  --audit /path/session-ticks.csv --events /path/session-events.csv \
  --reference /path/reference-ticks.csv --rates /path/reference-rates.csv \
  --requests /path/reference-requests.csv --metadata /path/reference-metadata.csv \
  --wire build/mt5/wire.jsonl \
  --snapshot build/mt5/engine-m1.json --snapshot build/mt5/engine-m15.json \
  --output build/mt5/verification.json
```

Коди завершення: 0 — надані перевірки пройшли для покритого діапазону; 1 — розбіжності/помилки; 2 — бракує доказів (wire, знімків, завершених свічок або спостереження хвоста еталонного потоку). Навіть код 0 не означає повноту всієї брокерської історії.

Перевіряються сирі поля, source_sequence, кількість/порядок wire-повідомлень, фаза history/live, HELLO/INFO/READY, Bid як chart_price, походження side, OHLC проти CopyRates й engine. Для OHLC допуск лише 1e-12 на представлення double, а розбіжності показуються в брокерських тіках. Завершені M1/M15 перевіряються лише на покритій області. Початок/кінець, некоректні записи, відсутні тіки та відсутні engine-свічки виводяться окремо. Відсутність тіків і відсутність бару сама по собі не доводить розрив котирувань: це може бути закрита сесія.

Перезапуск MT5 потрібно перевірити окремо: новий session, повторні INFO/HELLO/READY, очищення старих даних у engine, збіг нового аудиту з wire, відновлення поточних тіків. Поточний стан Connected цього не доводить.

## Автоматизовані перевірки

```bash
cmake --build build/cmake --parallel 2
ctest --test-dir build/cmake --output-on-failure
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s engine/tests -p 'test_*.py'
```

MQL contract-тест адаптує тільки синтаксис масивів/директив для C++ і виконує код кандидата з контрольованими MQL API. Оригінальні класифікатори витягуються з архівного 1.00, а не переписуються в тесті. MetaEditor окремо перевіряє справжню MQL-компіляцію. Тестова підстановка API не відтворює всі особливості Wine/MT5; потрібна реальна сесія після погодженого встановлення.

Бенчмарк незміненого агрегатора:

```bash
c++ -std=c++20 -O3 -pthread -I engine/include \
  engine/tests/fixtures/engine_bid_benchmark.cpp engine/src/ClusterAggregator.cpp \
  -o build/mt5/engine_bid_benchmark
./build/mt5/engine_bid_benchmark
```

Він вимірює агрегатор, не сумарний час Wine, мережі, CSV-аудиту чи промальовування UI.

Межа гарантій: протокол MT5 не надає унікальний ID кожного котирувального запису, а поточний TCP-протокол не містить ACK для кожного TICK. Позиційний курсор зберігає кратність записів за умови стабільного префікса історії; повністю однакові записи зберігаються як окремі позиції. Переписування історії з ідентичними полями неможливо відрізнити лише за цими полями. При видимій зміні префікса виконується повне відновлення сесії.

Курсор перевіряє граничну мілісекунду; ретроспективні виправлення брокером уже пройдених старіших мілісекунд автоматично не перечитуються. Їх виявляє незалежна звірка, після чого потрібне повне перезавантаження сесії.
