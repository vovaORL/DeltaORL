# DeltaORL

Термінал об’ємно-кластерного аналізу для Windows x64 та Linux x64: C++20 ядро, MetaTrader 5, React/TypeScript і Canvas 2D у вікні Electron. Візуальний інтерфейс містить footprint, профіль видимих свічок, об’єми, CVD, RSI та Stochastic.

## Запуск

Запустіть `DeltaORL.bat` або `start_all.bat`. Electron використовує `ui/dist`, перевіряє готовність ядра і запускає `engine/delta_engine.exe`, якщо порт 9191 вільний. Якщо вихідні файли новіші за збірку, застосунок спочатку запускає `build.ps1`. Помилки запуску показуються у діалоговому вікні.

Без доступного MT5 працює демонстраційний потік. Після handshake від MT5 демонстраційні дані очищуються та замінюються брокерськими. Після від’єднання демонстраційна історія створюється заново, без змішування джерел.

Окремі запуски:

- `run_engine.bat` — ядро.
- `run_ui.bat` — Vite на `http://127.0.0.1:3000`.
- `engine/delta_engine.exe --no-feeder` — ядро для MQL5-радника без автоматичного Python-підключення.
- `engine/delta_engine.exe --no-demo` — очікування реальних даних без демонстрації.

Обидва сервери доступні тільки локально: TCP 9190 для MT5, WebSocket 9191 для UI. Для тестів доступні параметри `--mt5-port N` та `--ws-port N`.

## Збирання

Потрібні Node.js/npm, MSYS2 UCRT64 GCC з C++20 або MSVC із CMake 3.20+. Python x64 та пакет MetaTrader5 потрібні тільки для прямого підключення до термінала.

```powershell
cd ui
npm.cmd ci
cd ..
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

Скрипт використовує `g++.exe` із PATH або `C:\msys64\ucrt64\bin\g++.exe`. GCC-збірка статично лінкує runtime, тому кінцевому користувачу не потрібні DLL компілятора. Перед заміною виконуваного файлу закрийте запущене ядро.

Параметр `-StageOnly` залишає новий виконуваний файл у `build/delta_engine.exe`, дозволяючи зібрати й перевірити оновлення поряд із запущеним старим ядром. Після закриття старого ядра Electron автоматично встановить цю актуальну збірку при наступному запуску.

Альтернатива для MSVC/GCC із CMake:

```powershell
cmake -S engine -B build/cmake
cmake --build build/cmake --config Release
ctest --test-dir build/cmake -C Release --output-on-failure
```

CMake не копіює результат у `engine`: для запуску через Electron покладіть зібраний `delta_engine.exe` у цю папку. У Windows ядро використовує Winsock і CryptoAPI, у Linux — POSIX-сокети та OpenSSL.

## Arch Linux / Sway

Потрібні `base-devel`, `cmake`, `openssl`, `nodejs` і `npm`. Electron встановлюється з `ui/package-lock.json`; системний Electron не потрібний. Застосунок використовує той самий React/Canvas-інтерфейс і C++-розрахунки, що й у Windows.

```bash
./DeltaORL.sh
```

Перший запуск встановлює npm-залежності та збирає застосунок. Наступні запуски перебудовують застарілі вихідні файли автоматично. У сесії Sway Electron використовує Wayland; для примусового запуску через XWayland можна задати `WAYLAND_DISPLAY= ./DeltaORL.sh`.

Збирання й перевірки окремо:

```bash
./build.sh --test
python3 -B -m unittest discover -s engine/tests -p 'test_*.py' -v
(cd ui && npm run test:smoke)
```

Ядро встановлюється в `engine/delta_engine`; тестова копія — у `build/delta_engine`. Окремий запуск: `./engine/delta_engine --no-feeder`.

MT5 у Linux працює через Wine ([документація MetaQuotes](https://www.metatrader5.com/en/terminal/help/start_advanced/install_linux)). Для прямого Python-підключення потрібні **Windows Python x64** та пакет `MetaTrader5` у тому самому Wine-префіксі, що й термінал. Приклад для вже налаштованого префікса:

```bash
export WINEPREFIX="$HOME/.mt5"
export DELTAORL_PYTHON='C:\Python312\python.exe' # Шлях до вашого Windows Python
wine "$DELTAORL_PYTHON" -m pip install -r "Z:$PWD/engine/requirements.txt"
./DeltaORL.sh
```

Без `DELTAORL_PYTHON` автоматичний Python-міст у Linux не запускається: доступні демонстраційний потік та підключення через наявний MQL5-радник `DeltaBridge`. У налаштуваннях можна вказати Linux-шлях до термінала чи його каталогу даних у Wine. Виявлення терміналів і встановлення радника використовують `WINEPREFIX` (типово `~/.wine`). Без підключеного брокера реальні дані перевірити неможливо.

## Підключення MT5

Прямий шлях: `engine/mt5_feeder.py` використовує офіційний Python-пакет MetaTrader5. Кореневий `mt5_feeder.py` є сумісною точкою входу до тієї самої реалізації.

```powershell
python -m pip install -r engine/requirements.txt
```

Якщо команда `python` у Windows веде на неробочий execution alias, задайте `DELTAORL_PYTHON` повним шляхом до справжнього `python.exe` перед запуском застосунку. Ядро також шукає встановлені інтерпретатори в локальних каталогах Python. Діагностика feeder записується в `engine/mt5_feeder.log`.

У вікні налаштувань можна вказати `terminal64.exe`, каталог встановлення або каталог даних MT5 із `origin.txt`. Сам термінал має бути підключений до брокера. Невдале підключення повертає повідомлення про помилку; запуск процесу не вважається підтвердженням підключення.

Альтернатива: запустіть ядро з `--no-feeder` і підключіть `mql5/DeltaBridge.ex5` до графіка MT5. Кнопка встановлення радника копіює `.mq5` і актуальний `.ex5` у `MQL5/Experts/DeltaORL` вибраного термінала. Після зміни `.mq5` перекомпілюйте його в MetaEditor. Python та радник є альтернативними постачальниками: ядро приймає одне TCP-з’єднання джерела одночасно.

Python завантажує до 200 000 тіків за 5 днів, розширюючи пошук до 10 днів за малої кількості даних. Поточний потік зберігає всі отримані записи з однаковою мілісекундною міткою. Обидва мости передають `READY` навіть за відсутності історії. Реальна глибина ринку передається тільки тоді, коли її підтримує брокер; для радника потрібен `InpSendBook=true`. За відсутності брокерського DOM ядро передає порожній стакан, а не штучну ліквідність.

Для Forex/CFD без напряму угоди й реального об’єму сторона визначається за рухом ціни, а відсутній об’єм замінюється одиницею. Така дельта є оцінкою за котируваннями, а не гарантованою біржовою дельтою.

## Архітектура і обмеження

`MT5Receiver` приймає `HELLO`, `INFO`, `TICK`, `DOM`, `READY`, `ERROR`. `ClusterAggregator` рахує OHLC, Bid/Ask, дельту, CVD, POC, VA 70% і діагональні дисбаланси. `WSServer` розсилає JSON через обмежені неблокувальні черги. UI застосовує знімки та оновлення свічок; RSI і Stochastic розраховуються на клієнті й кешуються до зміни даних.

Стан інструмента, таймфрейму та дисбалансів спільний для всіх вікон. Ядро тримає до 300 000 сирих тіків і 5 000 свічок; UI — до 1 000 свічок. Перебудова таймфрейму використовує доступний буфер тіків, зберігаючи базу CVD для вже витіснених тіків. Власної бази історії немає.

`MT5FileReader` підтримує CSV/TSV-експорт MT5 та сирі packed `MqlTick` записи по 60 байтів. Внутрішній формат кешів MT5 не вгадується за випадковими зсувами. Файлові парсери є API ядра; окремої панелі імпорту немає. Компоненти Time & Sales, DOMWidget і окремий VolumeProfile залишаються поза поточним компонуванням UI.

## Перевірки

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
python -m unittest discover -s engine/tests -p "test_*.py" -v
cd ui
npm.cmd run test:smoke
```

C++ перевірки покривають агрегацію, POC/дельту, закриття свічок, перебудову, конкурентний доступ, CVD після витіснення історії, JSON та CSV. Python перевіряє cursor тіків, відновлення сокета і повний TCP/WebSocket-протокол на ізольованих портах без брокера. UI-тести перевіряють злиття свічок, індикатори й відписування обробників. Electron smoke відкриває приховане тестове вікно з окремим профілем, перевіряє Canvas/дані/налаштування і зберігає `build/ui-smoke.png`.

Заяв про гарантовані FPS або кількість тіків за секунду немає: ці показники потребують вимірювання на цільовому обладнанні.
